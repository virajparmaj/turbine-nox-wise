# Impeccable Project Context

## Product
Engineering decision-support tool for turbine NOx emissions prediction. Operators or engineers input turbine parameters (temperature, pressure, fuel mix, load, etc.), submit to a Python ML backend, and receive predicted NOx values with supporting visualizations — trend charts, sensitivity analysis, and operational recommendations.

## Users
Turbine operators, emissions compliance engineers, and industrial data scientists. They read charts fluently and expect precise, labeled outputs with units. High stakes — incorrect predictions affect regulatory compliance.

## Visual Style
Engineering-grade technical UI. Serious, precise, and dense. Dark default with subtle blue-grey industrial palette. Should feel like SCADA software or a professional simulation tool — authoritative, not consumer.

## Colors
Primary: Steel Blue (#3B82F6) — primary inputs, chart series, active state
Secondary: Slate (#64748B) — labels, axes, metadata, secondary text
Accent: Orange (#F97316) — predicted NOx values, warning thresholds, alerts
Safe: Emerald (#10B981) — within-limit indicators
Danger: Red (#EF4444) — over-limit predictions, out-of-range inputs
Background: Slate-900 (#0F172A) / Slate-50 (#F8FAFC) in light mode
Text: Slate-100 (#F1F5F9) dark / Slate-800 (#1E293B) light

## Typography
Inter or system-ui for labels and body. Monospace (JetBrains Mono) for numeric outputs, NOx values, and parameter readouts. Tabular numerics everywhere data appears. Dense but readable — 13–14px in data panels.

## Layout & Spacing
Two-column: left panel for parameter inputs (form), right panel for output visualizations (Recharts). Mobile: stacked single column. Inputs grouped logically (combustion params / environmental params / operational params). Charts stack vertically in output panel. Tight spacing within input groups (8px), relaxed between groups (24px).

## Components
- Parameter input form with numeric inputs + unit labels
- Input validation with range indicators (min/max bands)
- Submit button with loading state during inference
- Predicted NOx output card (large value + unit + compliance status)
- Line/area chart for NOx trend vs parameter sweep
- Sensitivity bar chart (feature importance)
- Operational recommendations list
- Historical run comparison table
- Threshold indicator (regulatory NOx limit line on chart)

## UX Principles
Inputs must show valid ranges inline — engineers need to know acceptable bounds without a manual. Predictions must display units (ppm, mg/Nm3) always. Compliance status (above/below threshold) must be immediately visible without scrolling. Form submission must not lose previously entered values on error.

## Anti-patterns to Avoid
- Charts without axis labels or units
- Ambiguous loading states during ML inference
- Hiding compliance status below the fold
- Rounding NOx predictions aggressively (preserve 2 decimal places)
- Consumer-style UI (rounded cards, pastel colors, playful copy)

## Notes for AI Edits
Backend ML inference API and Zod validation schemas are off-limits. Chart types (Recharts) are intentional for engineering readability — do not swap to decorative chart libraries. Safe to modify: colors, spacing, input layout, typography, output card design. Maintain engineering-tool aesthetic — no softening toward consumer UI.
